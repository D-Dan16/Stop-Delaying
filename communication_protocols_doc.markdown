# פרוטוקולי תקשורת (Server-Client ו-API)

האפליקציה "Procrastination" מתבססת על ארכיטקטורת **BaaS (Backend as a Service)** המנוהלת בענן של Firebase ו-Google. מבנה זה מאפשר תקשורת מאובטחת ומהירה בין המכשיר לשרת ללא צורך בתחזוקת שרת פיזי.

#### 1. WebSockets וסנכרון בזמן אמת
התקשורת המרכזית מול ה-Realtime Database מתבצעת בפרוטוקול **WebSockets**. בניגוד לבקשות HTTP רגילות, פרוטוקול זה שומר על ערוץ פתוח ודו-כיווני. כך השרת יכול "לדחוף" (Push) עדכונים לאפליקציה באופן מיידי (למשל, עדכון ציונים בלוח המובילים) ללא צורך בפעולה יזומה מצד המשתמש.

#### 2. פרוטוקול HTTPS ואימות משתמשים
כל העברת הנתונים מוצפנת ומאובטחת באמצעות פרוטוקול **HTTPS** (Port 443). תהליך האימות מול Firebase Auth מתבצע באמצעות אסימוני אבטחה (**JWT - JSON Web Token**). לאחר ההתחברות, המכשיר מחזיק ב-Token המאפשר גישה מורשית בלבד לנתוני המשתמש במסד הנתונים, בהתאם לחוקי האבטחה שהוגדרו בשרת.

#### 3. ממשק RESTful API (בינה מלאכותית)
השירות לניתוח משימות חכם מתקשר עם שרתי Google דרך **REST API**. האפליקציה שולחת בקשות POST אסינכרוניות המכילות את נתוני המשימות, ומקבלת תשובה מנותחת ממודל ה-AI (Gemini 1.5 Flash). השימוש בבקשות אסינכרוניות מבטיח שממשק המשתמש לא "ייקפא" בזמן ההמתנה לעיבוד הנתונים בענן.

#### 4. פורמט הנתונים JSON
השפה המשותפת להעברת המידע בין כל רכיבי המערכת היא **JSON**. האפליקציה מבצעת סריאליזציה לאובייקטים של Java (כגון משימות ומשתמשים) לפורמט טקסטואלי מובנה זה, מה שמאפשר המרה מהירה וקלה של נתונים בין המכשיר, מסד הנתונים וה-API של הבינה המלאכותית.
